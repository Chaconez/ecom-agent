## 排查：NAS 上对话过程中 502 Bad Gateway

**结论**：502 由 Lucky（n.chacone.fun:8096 反代）产生，不是后端崩溃。Lucky 在 **10 秒** 处掐断并返回
`Lucky Warning / 502 Bad Gateway`；nginx 侧因此只记录 **499**（客户端断开），所以 nginx 日志里看不到 502。

**根因链**：
1. `agentscope.mcp.orizn-mcp`（差旅遗留签证 MCP）用 `npx -y orizn-visa-mcp` 启动，
   temurin:21-jre 容器无 npx → `StdioClientTransport` 每次卡满 `initialization-timeout-seconds: 20`
2. 后端 `ChatAgentExecutor.createEmitter()` 只 `new SseEmitter(1800000)`，**不立即 send**，
   响应头要等第一个业务事件才提交 → 首字节被 MCP 阻塞到 20 秒
3. Lucky 反代 10 秒等不到首字节 → 502
4. 直连 `http://192.168.3.3:8095`（绕过 Lucky）同一请求 31.88s 正常 SSE 200

**实测证据**（2026-10-27 02:02~02:05）：
- 走 8096：`HTTP=502 total=10.07s`，响应体为 Lucky 错误页；重测 `ttfb=10.12s` 仍 502
- 直连 8095：`HTTP=200 total=31.88s`，SSE 事件完整（thinking/progress/message/suggestions）
- nginx access log：`POST /api/chat/*` 共 8 次 —— 走 8096 的 7 次全 499，直连 1 次 200
- 后端日志：请求 02:04:36.001 → `MCP server starting` 02:04:36.211 → 直到 20s 超时才继续

**修复方向**：
- 必须：Lucky 后台调大该反代规则超时（10s → 300s 或 0）
- 建议：后端 `createEmitter()` 后立即发一帧注释/心跳，提前提交响应头；SSE 周期心跳
- 建议：禁用 `orizn-mcp`（电商项目不需要），省掉每次对话 20 秒白等

**次要问题（非 502 主因）**：客户端断开时后端抛
`IllegalStateException: Sinks.many().unicast() sinks only allow a single Subscriber` +
`HttpMessageNotWritableException: No converter for LinkedHashMap with preset Content-Type 'text/event-stream'`
（GlobalExceptionHandler 试图用 JSON 写 SSE 响应），会产生大量错误日志。
